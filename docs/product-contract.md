# Карта контракта каталога товаров DummyJSON

<!-- Карта разделена на два слоя: транспортные факты и форму ответа. Это помогает не смешивать URL, статус и поля JSON в один список. -->

## Сценарий поиска

### Транспортные факты

| Поле | Значение |
|---|---|
| Метод | `GET` |
| Template path | `/products/search` |
| Query-параметр | `q` |
| Пример запроса | `/products/search?q=phone` |
| Успешный status | `200` |
| Content-Type | содержит `application/json` |

<!-- Здесь фиксируем только форму ответа. Конкретные значения зависят от запроса и не нужны для контракта. -->
### Форма данных ответа

- `products` — массив объектов товаров
- `total` — общее количество найденных товаров
- `limit` — лимит элементов в ответе

## Сценарий деталей

### Транспортные факты

| Поле | Значение |
|---|---|
| Метод | `GET` |
| Template path | `/products/{id}` |
| Пример запроса | `/products/1` |
| Успешный status | `200` |
| Content-Type | содержит `application/json` |

<!-- Для details важно зафиксировать шаблон пути, а не конкретный id из примера. -->
### Форма данных ответа

- `id` — идентификатор товара
- `title` — название товара
- `price` — цена товара

## Smoke-набор

<!-- Smoke-набор повторяет два базовых сценария и проверяет только то, что контракт не сломался по форме и статусу. -->
1. **Поиск товаров**
   - Запрос: `GET /products/search?q=phone`
   - Ожидаемый status: `200`
   - Ожидаемый `Content-Type`: содержит `application/json`
   - Ожидаемая форма ответа: объект верхнего уровня содержит `products` (array), `total` (number), `limit` (number)

2. **Получение деталей товара**
   - Запрос: `GET /products/1`
   - Ожидаемый status: `200`
   - Ожидаемый `Content-Type`: содержит `application/json`
   - Ожидаемая форма ответа: объект содержит `id` (number), `title` (string), `price` (number)
